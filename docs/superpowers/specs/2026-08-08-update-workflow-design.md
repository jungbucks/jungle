# 정글 업데이트 워크플로우 설계 (2026-08-08)

## 왜 이 문서가 필요한가

정글의 검증 하네스는 이미 강하다. `verify.mjs` 5게이트, 단위 테스트 249건, pre-commit 자동 강제. 그런데 2026-08-07에 고친 결함 두 건은 그 그물을 그대로 통과했다.

- **ABCDE 모달 제목이 내부 저장 키를 노출** — `openAchvModal`이 `ACHIEVEMENTS` 조회 키를 제목으로 겸용해, 접미사가 붙는 고등학교 정보(`_고`)·정보과학(`_cs`) **9개 단원**에서 제목이 단원명과 어긋났다. 27개 단원 중 18개는 멀쩡했다.
- **평가계획 미리보기 표에서 한 행의 셀 하나만 정렬이 달랐다** — 같은 행의 수행평가·합계 칸은 가운데인데 정기시험 칸만 좌측.

두 결함의 공통점: **계산이 아니라 "화면에 무엇이 찍히는가"의 문제**였고, 둘 다 사용자가 눈으로 보다가 발견했다. `verify [5]`는 계산 로직만 본다.

같은 날 또 하나가 드러났다. `assets/style.css`의 모바일 반응형 작업이 **커밋되지 않은 채 세션을 넘어와 있었다.** 발견도 새고, 작업도 샜다.

이 문서는 두 구멍을 막는다. **① 렌더된 결과를 지키는 그물 ② 발견을 흘리지 않는 큐.**

## 확정된 결정

| 항목 | 결정 | 버린 것과 그 이유 |
|---|---|---|
| 회귀 방지 | 렌더 불변식 검사 (상시) | 스냅샷 승인제 — 데이터만 고쳐도 diff가 쌓여 매번 눈으로 훑어야 함. 픽셀 diff — 폰트·환경에 흔들려 거짓 실패 |
| 렌더 획득 | DOM 스텁 위에서 실제 렌더 함수 호출 | 소스 텍스트 정규식 — "코드에 그렇게 쓰여 있다"만 증명한다. 위 ABCDE 결함(코드는 멀쩡, 데이터 조합에서 9/27만 어긋남)을 못 잡는다 |
| 브라우저 검사 | `--visual` opt-in | 상시 게이트로 쓰기엔 수십 초. pre-commit을 느리게 만들면 사람이 훅을 끈다 |
| 발견 포착 | 레포 안 `INBOX.md` | 사이트 내 신고 버튼 — 공개 사이트에 UI를 심는 일이고 결국 붙여넣는 손은 남는다. ROADMAP §0 통합 — 장기 계획과 잡음이 섞여 둘 다 흐려진다 |
| 세션 루틴 | SessionStart + Stop 훅 둘 다 | 지침만 — 모델이 잊으면 그대로 샌다 |

## 구조

```
tools/
  verify.mjs       기존 [1]~[5]  +  [6] 렌더 불변식(상시)  +  [7] --links  +  [8] --visual
  render.mjs       신규 — DOM 스텁으로 각 화면을 렌더해 "화면 카탈로그"를 만든다
  invariants.mjs   신규 — 규칙 목록. 사람이 읽고 늘리는 곳
  visual.mjs       신규 — --visual 전용. 로컬 정적 서버 + 헤드리스 Edge
  session-brief.mjs  신규 — SessionStart 훅이 부른다
  session-check.mjs  신규 — Stop 훅이 부른다
```

기존 `[6] --links`는 `[7]`로 밀린다. 새 상시 단계가 `[6]`을 가져간다.

**의존은 한 방향이다.** `render.mjs`는 화면을 만들고, `invariants.mjs`는 그것을 읽기만 하고, `verify.mjs`는 둘을 붙여 판정만 한다. 셋은 서로의 내부를 모른다. `invariants.mjs`를 여는 사람은 렌더가 어떻게 되는지 몰라도 규칙을 늘릴 수 있어야 한다.

### 화면 카탈로그

이 설계의 심장. 화면 하나가 아니라 **데이터 조합마다 한 장**이다.

```js
{
  id: 'achv/high/데이터',
  kind: 'achvModal',
  html: '<div class="achv-modal">…',
  meta: { 과목: '고등학교 정보', 단원: '데이터', 코드: ['12정02-01', …] }
}
```

`meta`는 "이 화면은 무엇에 대한 것인가"의 정답지다. 규칙은 `html`과 `meta`를 대조해 어긋남을 찾는다. 제목이 단원명을 포함하는지 검사할 수 있는 이유가 `meta.단원`이 있기 때문이다.

**1단계 커버 범위 (5종)** — 전 화면 커버는 시도하지 않는다.

| kind | 장수 | 왜 이것부터 |
|---|---|---|
| `achvModal` | 27 | 2026-08-07 결함 발생 지점, 데이터 조합 다수 |
| `achvSemester` | 3~5 | 같은 모듈의 형제 화면 |
| `domainHeader` | 27 | 단원명·개수·해설 토글이 데이터와 맞물림 |
| `evalPreview` | 3~5 | 2026-08-07 정렬 결함 발생 지점 |
| `stdCard` | 표본 20 | 사용자 입력·이스케이프 경로 |

`evalplan`·`gradecalc`·`chasi`처럼 모듈 내부 상태에 의존하는 화면은 상태 주입구가 필요하다. **이미 있는 `__evalTest`·`__gcTest`·`__chasiTest`·`__achvTest`·`__affTest` 관례를 그대로 확장한다** — 새 발명이 아니라 기존 규약의 연장이다. 앱은 계속 render 함수만 쓴다.

### 규칙의 모양

```js
{
  id: 'achv-title-no-internal-key',
  왜: '모달 제목은 사용자가 읽는 이름이다. ACHIEVEMENTS 조회 키(_고/_cs)가 새면 단원명과 어긋난다.',
  대상: 'achvModal',
  검사: s => /_고|_cs/.test(제목(s)) ? `제목에 키 노출: ${제목(s)}` : null,
  가짜: { html: '<span id="achvModalTitle">데이터_고 — ABCDE</span>', meta: { 단원: '데이터' } },
}
```

`왜`는 한글 필수다. 6개월 뒤 규칙이 실패했을 때 "이게 왜 규칙이지"를 되묻지 않기 위해서다. `검사`는 위반 사유 문자열 또는 `null`을 돌려준다. 참/거짓이 아니라 **문장**을 돌려주는 이유는, 실패 메시지가 곧 수정 지시가 되어야 하기 때문이다.

### 시작 규칙 7개

| id | 무엇을 지키는가 | 2026-08-07 결함을 잡는가 |
|---|---|---|
| `achv-title-no-internal-key` | 제목에 `_고`/`_cs` 접미사 노출 금지 | ✅ 9건 |
| `modal-title-matches-unit` | 모달 제목은 `meta.단원`을 포함 | ✅ |
| `table-row-align-consistent` | 표 한 행의 데이터 칸은 정렬이 서로 같음 | ✅ 평가계획 표 |
| `all-codes-rendered` | `meta.코드`가 전부 화면에 등장 | — |
| `copy-matches-screen` | 복사본(TSV/HTML)과 화면 내용 일치 | — |
| `user-input-escaped` | 사용자 입력이 이스케이프 없이 렌더되지 않음 | — |
| `no-hardcoded-hex` | 렌더된 화면 마크업에 리터럴 hex 금지 | CLAUDE.md 규칙 5를 자동화 |

`no-hardcoded-hex`의 대상은 **화면 카탈로그의 `html`**이지 소스 파일이 아니다. CLAUDE.md 규칙 5의 예외(한글·워드 붙여넣기용 HTML을 만드는 `achv.js`·`rubric.js`·`evalplan.js`의 복사 빌더)는 화면이 아니라 복사본이므로 카탈로그에 애초에 들어오지 않는다 — 예외 목록을 따로 관리할 필요가 없다.

### 규칙은 결함에서 자란다

CLAUDE.md에 규칙으로 못 박는다: **결함을 고칠 때 그 결함을 잡았을 규칙을 함께 추가한다.** 위 7개 중 3개가 2026-08-07 결함에서 나온 시드다. 이 순환이 없으면 규칙 수는 첫날 이후 늘지 않는다.

## INBOX.md

레포 루트. CLAUDE.md 옆이 가장 눈에 띈다.

```markdown
## 미처리
- 2026-08-08 평가계획 표 좌측 라벨이 길면 잘림 (폰)

## 처리됨 (최근 20건만)
- 2026-08-07 ABCDE 모달 제목 키 노출 → 6244c9c + 규칙 achv-title-no-internal-key
```

**수명주기**: 사용자가 한 줄 던짐 → 모델이 날짜·맥락을 붙여 `미처리`에 append → 고치면 `처리됨`으로 옮기며 **커밋 해시와 추가한 규칙 id**를 남김.

규칙 id가 비어 있는 처리 항목은 그 자체가 빚이다. 이 한 줄이 위 "결함 → 규칙 승격"을 강제하는 유일한 증거다.

30일 넘게 남은 미처리 항목은 세션 시작 때 "아직 유효한가"를 묻는다. 조용히 쌓인 큐는 큐가 아니다.

## --visual

**픽셀 비교를 하지 않는다.** 로컬 정적 서버(node 내장 http)로 정글을 띄우고 헤드리스 Edge로 접속하되, 하는 일은 둘이다.

1. **브라우저에서만 알 수 있는 계산값 단언** — 예: 한 행 셀들의 computed `text-align`이 실제로 같은가. `[6]`은 인라인 style 문자열까지만 보므로 CSS 파일에서 오는 정렬은 여기서만 잡힌다.
2. **스크린샷 산출** — 사람이 보는 용도

기준 이미지 diff는 폰트·환경에 흔들려 거짓 실패를 만든다. **거짓 실패가 몇 번 나면 그 검사는 무시당한다.**

`file://`은 ES 모듈이 안 뜨므로 정적 서버가 필수다. 좁은 뷰포트는 헤드리스 창 최소폭 문제로 iframe 프로브를 쓴다(홈 루트 CLAUDE.md 함정 목록).

## 하네스 자체를 어떻게 믿는가

세 겹이다.

1. **규칙마다 일부러 깨진 가짜 화면** — 하네스는 매번 "이 규칙이 그 가짜를 실제로 잡는가"를 확인한다. 없으면 영원히 통과만 하는 죽은 규칙이 쌓이고, **그물이 있다는 착각만 남는다.**
2. **카탈로그 최소 장수 단언** — 27장이어야 하는데 3장이면 실패. 렌더가 조용히 죽어 "위반 0건"으로 통과하는 것이 이 종류 하네스의 대표적 사망 원인이다.
3. **`[1]~[5]`는 그대로** — 새 단계가 기존 그물을 대체하지 않는다.

## 실패 처리

- 화면을 못 렌더하면 **조용히 건너뛰지 않고 그 자체를 실패**로 본다. 빈 카탈로그로 전건 통과하는 것이 최악이다.
- 오탐이 나면 규칙에 `보류: '이유'`를 달아 끈다. **이유 없는 비활성화는 금지.**
- `[6]` 실패 메시지는 위반 화면의 `id`와 규칙의 `왜`를 함께 출력한다.

## 속도 예산

`[6]`은 pre-commit에서 매번 돈다. **목표 1초 이내.**

넘으면 규칙을 줄이는 게 아니라 **렌더 범위를 줄인다.** 규칙은 자산이고 범위는 조절기다. 이 우선순위를 뒤집으면 하네스가 서서히 비어간다.

## 단계적 도입

| 단계 | 내용 | 끝나면 |
|---|---|---|
| 1 | `render.mjs` + `invariants.mjs` + 규칙 3개 + `verify [6]` + 링크 `[7]`로 이동 | 결함 ②(표 정렬)는 배포 전에 잡힌다. 결함 ①(제목 키 노출)은 **절반만** 잡힌다 |
| 2 | 규칙 7개로 확장 + `INBOX.md` + 훅 2개 | 발견이 안 새고, 세션이 안 샌다 |
| 3 | `--visual` | 릴리스 전 모양 확인 |

각 단계는 독립적으로 쓸모가 있다. 1단계에서 멈춰도 손해가 아니다.

**1단계의 알려진 한계 — 결함 ①은 절반만 잡힌다.** `render.mjs`는 `openAchvModal(key, subj.accent, subj.name + ' · ' + d.name)` 처럼 표시 라벨을 **직접 조립해서** 넘긴다. 이는 `assets/app.js`의 호출부 표현식을 베낀 것이지, 앱에서 실제로 얻어온 값이 아니다. 그래서 `achv.js` 내부에서 제목 조립이 다시 깨지는 재발(예: 원래 결함 ①)은 잡지만, **`app.js`의 호출부 자체가 라벨 대신 조회 키(`achvKey`)를 넘기도록 되돌아가는 재발은 1단계가 못 잡는다** — 1단계는 호출부를 렌더하지 않기 때문이다. 이 구멍은 2단계의 `domainHeader` kind(호출부를 포함해 렌더)가 채운다. 그 전까지는 `app.js` 호출부 변경을 리뷰에서 사람이 봐야 한다.

**구현 계획은 1단계만 먼저 쓴다.** 2·3단계는 1단계가 실제로 결함을 잡는 걸 본 뒤에 계획한다 — 안 그러면 검증되지 않은 가정 위에 두 단계를 더 쌓게 된다.

## YAGNI로 버린 것

전 화면 커버(5종부터), 픽셀 diff, 스냅샷 승인제, 사이트 내 신고 버튼, **다른 28개 프로젝트로의 일반화** — 정글에서 검증된 뒤에 얘기한다.
