# 정글 배포 전 검증 (verify)

GitHub에 push하기 **전에** 반드시 실행. 이번에 겪은 "사이트 전체 백지" 같은 사고를 배포 전에 잡는다.

## 실행

```powershell
cd D:\Works\jungle
node tools/verify.mjs
```

- **종료코드 0** = 모든 검증 통과 → 배포 안전
- **종료코드 1** = 문제 발견 → 배포 중단 (어느 파일이 왜 깨졌는지 지목됨)

## 검사 항목

| # | 검사 | 왜 필요한가 |
|---|------|-------------|
| 1 | **import/export 정합성** | import한 이름이 실제 export 안 됐으면 브라우저에서 모듈 그래프 전체가 죽어 화면이 백지가 된다. `node --check`로는 못 잡는다. |
| 2 | **파일별 문법** | 깨진 파일을 **정확히 지목**한다. |
| 3 | **전체 그래프 로드 + init 실행** | `node --check`가 통과해도 실제 로드 시 터지는 런타임 초기화 오류를 잡는다. (렌더 함수 손상, 정규식 치환 사고 등) |
| 4 | **SW 프리캐시 파일 존재** | `sw.js` ASSETS 목록의 파일이 하나라도 없으면 `cache.addAll`이 통째로 실패해 서비스워커가 안 깔린다. 파일 추가/이름변경 후 필수. |
| 5 | **계산 로직 단위 테스트** | gradecalc·chasi·evalplan·achv·affective의 순수 계산 회귀. 성적·차시 계산이 조용히 틀리는 것을 막는다. (`tools/test.mjs` + `tools/workflow-tests.mjs`) |
| 6 | **렌더 불변식** | 계산이 아니라 **화면에 무엇이 찍히는가**를 지킨다. 화면을 데이터 조합마다 렌더해 규칙을 건다. 2026-08-07 모달 제목·표 정렬 결함이 이 그물에 안 걸려서 만들었다. (`tools/render.mjs` + `tools/invariants.mjs`) |
| 7 | **외부 링크 생존** | `--links` 플래그 시에만. 네트워크 의존이라 기본 게이트에서 제외. (`tools/linkcheck.mjs`) |

> `[6]`의 규칙을 늘리는 법은 CLAUDE.md 절대 규칙 13번 참고. 규칙에는 한글 `왜`와 일부러 깨진 `가짜` 화면이 반드시 붙는다.

## 권장 워크플로

1. 코드 수정
2. `node tools/verify.mjs`
3. ✅ 통과하면 → `sw.js`의 `CACHE` 버전 올리고 → commit & push
4. ❌ 실패하면 → 지목된 파일 수정 후 2번부터 반복

## 네거티브 테스트 (검증기 자체가 살아있는지 확인)

아무 `assets/*.js` 끝에 `}` 하나를 임시로 넣고 실행 → `[2]`와 `[3]`에서 잡히고 종료코드 1이 나오면 정상. 확인 후 반드시 원복.

## 사용자 흐름 회귀 (2026-09-09)

`node tools/workflow-tests.mjs`는 실제 앱 이벤트와 생성된 CSV·클립보드 내용을 검사한다. verify [5]에서 별도 프로세스로 자동 실행한다. 응시 여부 왕복, 첫 행 보존, 합계, 세 시간대의 월 경계, 과목 고정, 평가방법 복사, 검사 대상 행·셀 누락을 다룬다. 도구 전용 파일이므로 서비스워커 프리캐시에 넣지 않는다.

새 입력 CSV는 기존 4열 뒤에 `1차응시`, `2차응시`(1=응시, 0=미응시)를 저장한다. 예전 4열 CSV는 기본 응시로 읽으며, 당시 저장하지 않은 미응시 정보는 복원할 수 없다. 산출결과 CSV는 입력 양식과 열 의미가 달라 업로드를 거부한다.

## 화면 검토 (로컬 전용)

앱 빌드나 npm 설정 변경 없이 실행한다. 미리보기는 Node만 필요하며 이 컴퓨터에서만 접속된다.

```powershell
node tools/ui-review.mjs serve
```

브라우저에서 http://127.0.0.1:4173 을 연다. 종료는 Ctrl+C.

UI 수정 절차:

1. 수정 전에 `node tools/ui-review.mjs before`
2. 코드 수정 후 `node tools/ui-review.mjs after`
3. 미리보기 서버를 실행하고 http://127.0.0.1:4173/.ui-review/index.html 에서 PC·모바일 전후 비교
4. 글자 잘림, 버튼 위치, 첫 목록까지의 거리, 여백을 확인하고 실제 메뉴를 오가며 사용감 확인
5. `node tools/verify.mjs` 통과 후 커밋

현재 캡처 대상은 교과서 페이지다. 1280×900과 360×800에서 전체 페이지를 저장하며 검색·과목 전환·빈 결과 안내·가로 넘침·JS 오류를 검사한다. 서비스워커를 차단한 새 브라우저 환경으로 실행하므로 예전 캐시가 섞이지 않는다. 메뉴는 앱의 실제 이벤트를 사용한다. 자동 검사가 디자인 품질을 보증하지는 않는다.

캡처에는 Playwright와 Edge가 필요하다. 로컬 설치 또는 Codex 번들 Playwright를 자동 탐색한다. 다른 설치는 `$env:JUNGLE_PLAYWRIGHT='설치된 playwright 폴더의 절대 경로'`로 지정한다. Chrome 사용 시 `$env:JUNGLE_BROWSER='chrome'`. 도구가 의존성을 자동 설치하지는 않는다.

결과는 `.ui-review/`에 저장되고 Git에서 제외된다. before/after는 각각 재실행 시 덮어쓰므로 보관할 비교는 따로 복사한다. 새 변경 작업 시작 전에는 두 캡처를 다시 실행한다. 개발 도구이므로 서비스워커 프리캐시에는 넣지 않는다.
